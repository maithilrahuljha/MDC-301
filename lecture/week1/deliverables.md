# Week 1 · Student deliverables checklist

Submit or point the instructor to your public course-repository URL. The grader should not need private information to find your work.

## Required

- [ ] Your Pages URL opens the repository root and links to `lecture/index.html`.
- [ ] `Settings → Pages` is configured for branch `main` and folder `/(root)`.
- [ ] `lecture/index.html` opens; Week 1 shows the four exact topic headings in order and links through all five session pages; Week 2–8 each show the correct “Coming in Week N” placeholder.
- [ ] The canonical `lecture/` files are unchanged for the release, except for an explicitly approved update.
- [ ] `exercises/week1/session1.py` through `session5.py` are present. Add your own solution/output notes only if they contain no private data.
- [ ] `progress.md` contains all five checked Week 1 lines using the exact IDs `W01-S01` through `W01-S05`.
- [ ] Add a short reflection in `progress.md`: one idea learned, one limitation you will check, and one next step.
- [ ] Add one short bug-fix note for each of the five sessions in `progress.md` (what fails, the fix, and one limitation).
- [ ] Complete the three existing poll checks linked from each session page; participation is recorded by the instructor’s separate polling tool, not by this static site.

## Optional

- [ ] Add a short note to `notes/` only if you accept that it is public.
- [ ] Opt in to the instructor URL gallery using a public site URL and a pseudonym if desired. Gallery participation is not required for credit.

## Do not commit

Passwords, tokens, API keys, student IDs, grades, personal contact details, real private datasets, private notes, or another person’s work. A public repository can be copied even after you delete a file; report and rotate exposed credentials immediately.
