Outline · selected derivation and practice path

Multiple and polynomial regression

Promise: add useful features to a linear model, derive the least-squares solution in matrix form, and spot when extra flexibility starts fitting noise.

Learning objectives

  • Write multiple regression as a feature matrix multiplied by a coefficient vector.
  • Explain the normal equations and when the inverse formula is not safe to compute directly.
  • Build polynomial features and describe the overfitting risk of unnecessarily high degree.

Three ways to build the feature table

Simple regression · one feature

\(\hat y=\beta_0+\beta_1x\). One input column predicts a numeric target.

Multiple regression · several features

\(\hat y=\beta_0+\beta_1x_1+\beta_2x_2\). Add a coefficient for each included input, such as engine size and vehicle age when predicting price.

Polynomial regression · transformed feature

\(\hat y=\beta_0+\beta_1x+\beta_2x^2\). Add powers such as \(x^2\) to let the fitted curve bend.

Why all three are still linear models

The curve may not be straight in the original input, but the prediction is still a linear combination of the coefficients \(\beta\). “Linear” here describes the parameters, not necessarily the plotted curve.

from sklearn.linear_model import LinearRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures

model = make_pipeline(
    PolynomialFeatures(degree=2, include_bias=False),
    LinearRegression()
)
model.fit(X_train, y_train)  # X_train contains training rows only

With one input column, degree 2 produces \(x\) and \(x^2\). With several columns, polynomial expansion can also create interaction terms. Keep the degree modest and compare candidates on validation data, not the test set.

Session outline

1 · More than one input

Interpret a coefficient while holding the other included features fixed; discuss scale and correlated features without overclaiming causality.

2 · Matrix least squares

Set the gradient of the squared-error objective to zero. Identify the feature-matrix shape and the intercept column.

3 · Curves from features

Map \(x\) to \((x,x^2,\ldots,x^d)\); the model stays linear in its coefficients even when its curve is not straight in the original input.

4 · Validate, do not peek

Compare degree choices using training/validation data. Keep the test set for one final, honest estimate.

Selected derivation · normal equations

For the augmented design matrix \(\tilde X=[\mathbf 1\mid X]\), minimize squared residuals. The first-order condition is:

\[S(\beta)=(y-\tilde X\beta)^T(y-\tilde X\beta),\qquad \nabla_\beta S=-2\tilde X^T(y-\tilde X\beta).\]

Setting the gradient to zero gives \(\tilde X^T\tilde X\hat\beta=\tilde X^Ty\). If the matrix is invertible, \(\hat\beta=(\tilde X^T\tilde X)^{-1}\tilde X^Ty\); in code, prefer a stable least-squares solver rather than forming the inverse.

Scope: custom booklet, Chapters 9–10, and the supplied linear-regression worksheets. For optional reference, see scikit-learn’s preprocessing guide for polynomial features and its cross-validation guide for evaluation with pipelines.

Break it / fix it · unnecessary polynomial complexity

A very high degree is not automatically a better model; it can follow noise and behave wildly between observed points:

poly = PolynomialFeatures(degree=20, include_bias=False)
X_poly = poly.fit_transform(X_train)
model.fit(X_poly, y_train)
print("train score only:", model.score(X_poly, y_train))
Show the fix and the lesson

Start with a degree justified by the data, compare candidates on validation/cross-validation, and consider regularization. A high training score is not evidence of generalization. Do not choose a degree by repeatedly checking the test score; reserve the test set for the final estimate.

Peer-visible moment: sketch the transformed columns \(x\) and \(x^2\) for one observation and explain why the coefficients remain linear parameters.
