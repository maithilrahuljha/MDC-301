Week 1 / Session 1

Outline · selected derivation and practice path

What machine learning does

Promise: turn a vague prediction request into a testable learning problem, and explain why success on unseen data matters more than a perfect training score.

Learning objectives

  • Identify the decision, input features, and target before choosing a model.
  • Distinguish supervised learning (known targets) from unsupervised learning (no target labels).
  • Place problem framing, splitting, fitting, evaluation, deployment, and monitoring in a responsible lifecycle.

Session outline

1 · Start with the decision

Service-monitoring story: estimate future station demand for staffing. State what one prediction changes before discussing algorithms.

2 · Label the table

Features are model inputs; the target is the value to predict. Ask whether the target is a quantity or a category.

3 · Supervised or unsupervised?

Use labelled demand examples versus grouping stations without labels. Reinforcement learning is named only as a third setting, not taught.

4 · The lifecycle

Frame → inspect data → split → fit → evaluate → deploy → monitor. Keep test data out of model selection.

Selected derivation · empirical risk

Start with the booklet’s “choose a function, define a loss, fit parameters” template. For examples \((x_i, y_i)\), average the per-example loss and choose parameters that minimize that average:

\[\widehat{\theta}=\arg\min_{\theta}\;\frac{1}{n}\sum_{i=1}^{n}L\bigl(f_{\theta}(x_i),y_i\bigr).\]

Contrast the training average with performance on unseen examples: the second is the generalization goal, not a quantity to optimize by repeatedly peeking at the test set.

Scope: custom booklet, Chapter 1, “An Overview of Machine Learning.” This is the planned board derivation for the outline session.

Break it / fix it · data leakage

This order lets the test distribution influence preprocessing before evaluation:

# Deliberately wrong: fit a transformation before the split.
X_scaled = scaler.fit_transform(X_all)
X_train, X_test, y_train, y_test = split(X_scaled, y_all)
Show the fix and the lesson

Split first. Fit each transformation on training rows only, then apply that fitted transformation to validation/test rows. A pipeline makes the order explicit. Keep the test set for the final report rather than repeatedly selecting models on it.

Peer-visible moment: if you opt in, share only your public Pages URL and one sentence naming your target. No names or student IDs are needed.

After this session, you can: name features and target, distinguish supervised from unsupervised learning, and describe a leakage-safe evaluation step.
