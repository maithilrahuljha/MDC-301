MDC-301 Week 1 public quiz — setup and classroom steps
====================================================

The quiz is a static public website. Students do not need a GitHub account, organization membership, app, or installation. Supabase response collection is optional; without it, answers are not uploaded.

What it does
------------
* Eight Week 1 topics, ten questions each.
* **Lecture mode:** the instructor gives cues for answering, revealing feedback, and moving on. Devices do not synchronize, and there is no live class-results screen.
* **Practice mode:** students get feedback after each answer and can retake any topic. Practice answers are never uploaded.
* This is a public formative quiz, not a secure exam. Question files, including answer keys, are public.

1. Publish with GitHub Pages
----------------------------
1. Open the public repository: https://github.com/maithilrahuljha/MDC-301 . Keep the repository public so anyone can use the quiz without signing in.
2. Open **Settings → Pages**. Under **Build and deployment**, select **Deploy from a branch**.
3. Select branch **main** and folder **/(root)**, then save. The root `index.html` redirects visitors to the quiz page. The app loads the existing topic JSON from its relative path, so no build workflow or extra software is needed.
4. Wait for GitHub Pages to finish its first deployment. Open the URL shown on the Pages settings screen; it will normally be `https://maithilrahuljha.github.io/MDC-301/`.
5. Test the URL in a private/incognito browser and on a phone. Confirm it opens without GitHub login and that a topic loads. Share this URL with students.

If Pages is blocked by institution policy, ask the repository administrator or IT administrator to enable it. Students never need GitHub credentials.

2. Run the quiz in class
------------------------
1. Students open the public URL and choose **Lecture mode** or **Practice mode**.
2. In Lecture mode, announce the topic and when to submit, reveal feedback, and advance. Each student advances their own screen after the cue; this static page does not synchronize devices or show live results.
3. If Supabase is enabled, give students the same session label. An optional alias may be entered; students can leave it blank.
4. After the lecture, students can choose Practice mode and retake the same topic or another topic at their own pace.
5. Test the page on the classroom Wi-Fi and a few real devices before class. Keep a paper/offline fallback; this cohort has not been load-tested.

3. Optional: collect lecture responses with Supabase
---------------------------------------------------
Skip this section if responses are not needed. The quiz works with the default blank settings and uploads nothing.

1. Use an instructor-owned Supabase project approved for course data. Students do not need Supabase accounts.
2. In the Supabase Dashboard **SQL Editor**, paste and run `week1/livequiz/pages/supabase_setup.sql`. It creates a response table with row-level security. Public visitors can insert rows but cannot read, edit, or delete them.
3. In **Project Settings → API**, copy the project URL and the public **anon/publishable** key. Edit `week1/livequiz/pages/config.js` and fill the two values:

       window.MDC301_SUPABASE = {
         url: "https://YOUR-PROJECT.supabase.co",
         anonKey: "YOUR-ANON-OR-PUBLISHABLE-KEY"
       };

   The URL and anon/publishable key are public browser settings. **Never put a `service_role` or secret key in this file.**
4. Commit the change and merge it to `main`. GitHub Pages updates from that branch. In Lecture mode, enter the instructor's session label; the page reports whether the answer was saved. Supabase stores responses for later review but does not display live totals. Practice mode never sends answers.
5. To review, sign in as the project owner, open the Supabase **SQL Editor**, and run:

       select submitted_at, session_code, topic_slug, question_id,
              question_type, answer_text, answer_index, is_correct, display_name
       from public.week1_quiz_responses
       order by submitted_at desc;

   Keep any export private and delete rows/exports at the approved retention date. To clear the table after the course, if permitted, run `delete from public.week1_quiz_responses;` in the SQL Editor.

Data and safety notes
--------------------
* The quiz sends a session label, topic/question IDs, answer, correctness for scored questions, optional alias, and submission time. It does not request a GitHub username, email, password, phone number, or student ID. Supabase may process technical/network metadata under its own policies.
* A session label groups answers; it is not a password. Anyone who finds the public page can try to insert rows. Field checks limit formats and lengths, but anonymous access cannot verify who submitted. Leave collection off if that risk is unacceptable. Do not use responses for grades, attendance, or high-stakes decisions.
* Tell students what is collected and how long it will be kept before enabling collection. Prefer anonymous answers or aliases; do not request sensitive personal information.
* GitHub Pages serves from the public repository branch. Keep private data, credentials, `.env` files, and response exports out of tracked files. The topic JSON files are public, including correct-answer indexes; this is not a secure exam.

Instructor maintenance
---------------------
* Edit source questions in `week1/livequiz/topic_banks/`. Run `python week1/livequiz/scripts/check_question_bank.py` from the repository root; expected output includes `topic_banks=8 topic_questions=80`.
* After changes are merged to `main`, GitHub Pages publishes the updated page and topic banks. If it does not update, check **Settings → Pages** and the repository's Pages deployment status.
* Leave both values in `config.js` blank when collection is off. Never commit a Supabase secret key, Flask `.env`, response export, or other credential.
* The separate Flask/Socket.IO app in `week1/livequiz/` remains available for an instructor-operated synchronized session; see `week1/livequiz/README.md`. It is not needed for this public quiz.
